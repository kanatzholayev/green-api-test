# Telegram-чат через GREEN-API

Минимальный интерфейс личной текстовой переписки: подключение своего Telegram-инстанса, создание чата по номеру телефона, отправка сообщения и получение ответа. React + TypeScript, Vite, MUI и `@mui/x-chat`; компоновка в духе веб-чата MAX. Стили компонентов лежат рядом с ними в SCSS modules.

В исходном задании смешаны Telegram и MAX. По согласованию реализован **только Telegram**, поэтому используются методы из `/telegram/docs/`, а не `/v3/docs/`.

## Запуск

Node.js 22.12+ (проверено на 22.23.1), npm.

```sh
npm ci
npm run dev
```

Откройте адрес, который напечатает Vite (обычно http://127.0.0.1:5173).

```sh
npm test          # обработка сообщений, очередь уведомлений, API-клиент
npm run lint      # ESLint для React/TypeScript и Stylelint для SCSS
npm run build    # строгая проверка TypeScript и production-сборка
npm run preview  # просмотр production-сборки
```

## Подключение

1. Создайте **Telegram-инстанс** в [кабинете GREEN-API](https://console.green-api.com/) и завершите его авторизацию. Требуется состояние `authorized`.
2. Скопируйте `idInstance`, `apiTokenInstance` и `apiUrl` в форму. Адрес берётся из кабинета, а не вычисляется из ID; например, `https://4100.api.green-api.com`.
3. Для получения нужны `incomingWebhook: "yes"` и пустой `webhookUrl`. Если настройки отличаются, приложение предложит изменить их кнопкой «Настроить получение». Очистка существующего webhook отключает доставку на прежний адрес. Применение настроек может занять до минуты.
4. Создайте чат по номеру с кодом страны, отправьте текст, ответьте со второго аккаунта Telegram. Полученный ответ появится в той же переписке.

Поиск получателя выполняется через `checkAccount`; полученный `chatId` используется и для отправки, и для сопоставления входящих. Если номер скрыт настройками приватности, поиск может не найти аккаунт. Ограничения поиска и тарифа GREEN-API отображаются как ошибки.

## Поведение

- Несколько личных чатов, переключение, счётчик непрочитанных, мобильная компоновка.
- Только текст, до 4096 символов. Enter отправляет, Shift + Enter переносит строку.
- Успешный `sendMessage` означает принятие сообщения API, а не подтверждение доставки. Статусы доставки/прочтения обновляются при поступлении соответствующих уведомлений; для них включите `outgoingWebhook`, `outgoingMessageWebhook`, `outgoingAPIMessageWebhook` в кабинете.
- При отказе API можно повторить отправку. При сетевом сбое результат может быть неопределённым: автоматического повтора нет, чтобы не отправить дубликат.
- Получение: один последовательный цикл `receiveNotification → обработка → deleteNotification`, long polling на 20 секунд. Ошибки повторяются с увеличением задержки, ошибки доступа останавливают получение. Повторные сообщения отбрасываются по ID.
- Нетекстовые и групповые сообщения не показываются; их уведомления подтверждаются, чтобы очередь продолжала работать. Очередь инстанса общая: используйте выделенный тестовый инстанс и одну вкладку приложения.
- Учётные данные, сообщения и чаты находятся только в памяти. Выход и обновление страницы очищают сессию. История Telegram не загружается.
- Прямые HTTPS-запросы идут из браузера в GREEN-API, без собственного backend. Токен не записывается в браузерное хранилище, логи приложения или репозиторий; согласно протоколу GREEN-API он присутствует в URL запросов к сервису.

## Архитектура FSD

```text
src/
  app/                        точка входа и тема MUI
  pages/chat/                 выбор экрана подключения или переписки
  widgets/chat-workspace/     сборка списка чатов, переписки и действий
  features/
    connect-instance/         подключение и проверка настроек
    create-chat/              поиск получателя по телефону
    send-message/             ввод и отправка текста
    receive-messages/         цикл получения и подтверждения уведомлений
  entities/chat/              сообщения, чаты, reducer, нормализация событий
  shared/api/                 клиент GREEN-API и типы протокола
  shared/lib/                 телефон и даты
```

Зависимости направлены вниз по слоям; у срезов есть публичные `index.ts`. Состояние реализовано через React `useReducer`, без отдельной библиотеки состояния.
Лента сообщений использует `ChatMessageList` из `@mui/x-chat`; отправка и статусы остаются в существующей модели GREEN-API. `@mui/x-chat` пока выпускается в alpha-версии, поэтому его интерфейс может измениться при обновлении зависимости.
